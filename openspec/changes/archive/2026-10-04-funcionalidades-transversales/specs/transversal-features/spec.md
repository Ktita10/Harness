# Capability: Transversal Features & Technical SEO Assets

## Requirements

### Requirement: Global Contextual Floating WhatsApp Button
The site SHALL display a persistent floating WhatsApp contact button at the bottom-right of every page (`/`, `/servicios/*`, and `/404`).

#### Scenario: Visual presentation and responsive placement
- GIVEN any route rendered on any viewport (360px mobile, 768px tablet, 1280px desktop)
- WHEN the page is loaded
- THEN the WhatsApp button SHALL be fixed at the bottom right corner with appropriate z-index and spacing
- AND it SHALL NOT cause horizontal scroll overflow (`scrollWidth === clientWidth`)
- AND it SHALL have an accessible label `aria-label="Contactar por WhatsApp"`
- AND external link attributes MUST include `target="_blank"` and `rel="noopener noreferrer"`.

#### Scenario: Contextual message pre-filling
- GIVEN a user navigating to a specific route
- WHEN inspecting the WhatsApp button `href` attribute
- THEN the URL SHALL match the pattern `https://wa.me/[phone]?text=[encodedMessage]`
- AND on the Home page (`/`), the query parameter SHALL contain a general consultation greeting
- AND on each Service page (`/servicios/[slug]`), the query parameter SHALL contain the service-specific inquiry message
- AND on the 404 page (`/404`), the query parameter SHALL contain a contextual lost-user assistance message.

### Requirement: Branded 404 Error Page
The site SHALL serve a dedicated static 404 error page at `/404` adhering to the neo-brutalist design system.

#### Scenario: 404 page structure and navigation
- GIVEN a user navigating to `/404` (or an unhandled route)
- WHEN the page renders
- THEN exactly one `<h1>` element SHALL be present reading "Página no encontrada"
- AND prominent neo-brutalist buttons SHALL provide navigation back to the Home page (`/`) and Services section (`/#servicios`)
- AND the floating WhatsApp component SHALL be visible with contextual messaging
- AND `/404` SHALL NOT be listed in `sitemap-index.xml`.

### Requirement: Favicon Asset Bundle and Declarations
The site SHALL provide and declare the complete set of favicon assets required by `SPEC.md` and `AGENTS.md`.

#### Scenario: Favicon head declarations
- GIVEN any page rendered using `Base.astro`
- WHEN inspecting the `<head>` element
- THEN `<link rel="icon" type="image/svg+xml" href="/favicon.svg" />` SHALL be present
- AND `<link rel="icon" type="image/png" sizes="32x32" href="/favicon-32x32.png" />` SHALL be present
- AND `<link rel="icon" type="image/png" sizes="192x192" href="/favicon-192x192.png" />` SHALL be present
- AND `<link rel="icon" type="image/png" sizes="512x512" href="/favicon-512x512.png" />` SHALL be present
- AND `<link rel="apple-touch-icon" href="/apple-touch-icon.png" />` SHALL be present
- AND all referenced image files SHALL exist in the `public/` directory and return HTTP 200.

### Requirement: Open Graph and Twitter Card Preview
The site SHALL declare valid Open Graph and Twitter Card metadata pointing to a branded preview asset.

#### Scenario: Social media preview tags
- GIVEN any page generated by the build
- WHEN inspecting the `<head>` metadata
- THEN `og:image` and `twitter:image` meta tags SHALL be present
- AND their `content` attributes SHALL contain absolute URLs resolving to an existing 1200x630 image asset (`og-image.png`)
- AND `twitter:card` SHALL be set to `summary_large_image`.

### Requirement: Robust JSON-LD Structured Data
The site SHALL emit valid, error-free JSON-LD schemas across all pages without malformed URL concatenations.

#### Scenario: Schema resolution and logo URL validation
- GIVEN the generated JSON-LD scripts on any route
- WHEN inspecting the `Organization` schema
- THEN the `logo` attribute SHALL be an absolute, valid URL pointing to `favicon.svg` (e.g., `https://harness.studio/favicon.svg`)
- AND no URL in any schema (`Organization`, `Service`, `BreadcrumbList`, `FAQPage`) SHALL contain double slashes or missing slashes.

### Requirement: Automated Verification
All transversal features SHALL be validated through automated Playwright tests in `tests/features.spec.ts`.

#### Scenario: Automated test execution
- GIVEN the test suite `tests/features.spec.ts`
- WHEN `npx playwright test tests/features.spec.ts` executes
- THEN all tests verifying WhatsApp floats, 404 page, favicon links, OG preview tags, and JSON-LD schemas SHALL pass with 0 failures across desktop and mobile viewports.
